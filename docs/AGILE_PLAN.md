# 投入产出网络韧性代码库敏捷建设规划

## 目标和当前判断

目标是全课题组共享的科研基础设施，而不是另一套只服务于一篇论文的大脚本。
我们采用短迭代、小纵向流程、分区并行和逐项复审：先交付能运行、能解释、能核验的一小段研究流程，再据反馈扩展。
建设方案中的 V1.0 至 V5.0 是能力路线，不是必须一次性完成的开发清单，也不是当前包的成熟度声明。

本规划依据用户提供的《投入产出网络韧性可复用GitHub代码库建设方案》及以下现场核查：

- 计划书文件 SHA-256：`c70e22d434ab6866a5d83b2d3786af807486d9ab3ad82d91f0f9d6f6344abb19`。
- 远程仓库：<https://github.com/chuxin710-commits/industrial-chain-io-network-workflow>。
- 起点提交：`7ab143c9ccc4bbe69e654fc2b2d40153f701907b`；核查日期：2026-09-30。
- 现有仓库主要有两套论文脚本和对应 Skill 副本，原始表没有随库分发；代码许可证为现有 MIT，不改作者署名。
- 本地另有 2000 至 2023 年省级 MRIO 实证代码和结果。它们不是上述仓库起点中的内容，未经迁移验收或数据授权检查，不直接复制进公开仓库。

第一轮只完成 `IO -> A/L -> directed network -> structural metrics -> traceable outputs`。
它不是已经完成的级联、功能韧性或恢复平台。先使一个课题组成员能在干净环境复现这个流程，再开展第二轮。

## 现状与优先风险

| 分区 | 现场发现 | 处理原则 |
| --- | --- | --- |
| 数据 | 旧 reader 依赖 DOM/OUTPUT 格式；另一 reader 用索引交集截取部门 | 新 adapter 不默默丢部门、不按位置错配 x；显式核对标签与口径 |
| 包与导入 | 旧脚本在模块顶层读取数据、运行分析、写文件；没有安装包和测试目录 | 新核心无导入副作用；保留旧脚本为历史入口，不直接 import |
| IO | `nan_to_num` 和伪逆会把无效输入或模型不可解情况掩盖 | 分清导入修复与模型计算；核心失败时显式拒绝 |
| 网络 | 旧关键节点脚本把依赖权重直接传给最短路算法 | 新网络独立记录 strength 与 distance；强边在倒数距离下更短 |
| 经济机制 | Ghosh 乘法方向和冲击变量经济含义需要复核 | 保持原结果，建立小例子和方法审查后另开结果变更 PR |
| 历史 SIR | 有条件模拟可复用，但不是逐行业产能级联 | 迁为明确命名的 legacy 插件，不产出伪造经济损失 |
| 来源 | MRIO 行业名称、单位、价格、2D-LQ 参数尚缺 | 保留原始代码与 unknown；内部平衡不等于外部来源认证 |
| 发布 | 核心 MIT 不代表源表、聚合表、论文和派生输出可公开 | 只分发人工合成样例；真实数据及派生值按许可单独审核 |

证据和可复现风险见 [数据审查](reviews/data_contract_review.md)、[科学内核审查](reviews/scientific_kernel_review.md)、[协作与复现审查](reviews/workflow_review.md)。
这些报告把静态发现、实际执行证据与尚未验证的建议分开。

## 并行分区和所有权

| 分区 | 写入范围 | 交付物 | 交叉复审 |
| --- | --- | --- | --- |
| A 数据与 IO 合同 | core、data adapters、对应 tests | IOSystem、核算口径、A/L、来源审计 | B 复核数学前提，D 复核来源记录 |
| B 网络与关键性 | network、importance、对应 tests | Z/A/L 视图、路径与中心性、关键性比较 | A 复核方向和归一化，C 复核解释 |
| C 冲击传播与双韧性 | shock、cascade、resilience、recovery | 模型接口、损失与恢复曲线 | A 复核经济恒等式，B 复核结构维度 |
| D 实验与质量 | experiment、CLI、CI、run artifacts | 配置、追溯、四层测试、发布门禁 | 非作者复查干净安装和失败边界 |
| E 教学与文档 | docs、examples、notebooks | 快速入口、教程、论文模板 | 新使用者照文档运行，不只校对文字 |

以上是职责，不是虚构已经指派的课题组人员；实际维护者名单和权限需课题组确认。
当前实现 WIP 上限为 3 个分区任务，同时保留整合复审能力。根集成者协调接口，不能自己写完后自己批准全部改动。
同一文件由一名作者拥有；跨分区改动先发接口说明，不同时改同一方法定义。已有实现可以继续并行，不必等待一整层架构做完。

## 小迭代的工作方式

建议每轮 1 至 3 个工作日；真实节奏根据组员可用时间调整。每个任务应能独立解释、验证、回退，不以代码行数验收。

1. 从 backlog 选一个小研究流程和最多三个并行实现任务；写清输入、输出、不做什么。
2. 先共享最小接口及人工 fixture。数据分区核算时，网络分区可用 fixture 实现，质量分区可同时写负例和 CLI 测试。
3. 每一处有行为意义的改动先复现原问题或给出预期结果，再改代码，再跑相关测试。
4. 非作者回读公式、参数、输入口径和失败行为；仅有“测试通过”不能代替科学复审。
5. 用一个真实使用方式演示：新环境安装、从任意工作目录运行、检查输出和追溯文件。
6. 把发现的新问题和结果变化写回 backlog；只有当前小流程通过才合并，未完成扩展继续保留为任务。

不设置“先几周写架构、再几周写算法、最后统一验收”的瀑布阶段。近期只细排两轮，远期功能保持候选池。

## 当前及下一轮

### 迭代 01 可安装与可追溯的结构分析

核心问题：一个未参与编程的组员能否理解并重跑最小流程？

- A 并行完成 IOSystem 输入合同、完整 A、严格 L 计算、显式 y 检查。
- B 并行完成 Z/A/L 网络、方向、绝对阈值、倒数距离、孤立节点和结构指标。
- D/E 完成配置驱动合成样例、独立输出目录、源代码/配置/数据指纹、CI 与协作模板。
- 使用人工三行业样例，不安装 Node2vec/GNN，不读真实授权表，不改旧论文数值。
- 验收：干净安装、手算/独立算法对照、输入负例、重复运行数值一致、拒绝覆盖和导入无副作用。
- 局部完成不等于远程 CI 通过；远程合并需实际 CI 和维护者复审。

### 迭代 02 真实表适配与关键性二维比较

核心问题：同一对象能否接入另一张表，同时解释经济重要性和结构重要性为什么不同？

- A 写国内分拆表/MRIO loader，先支持单年与标签强对齐，保留 F、E、进口及输入/输出调整项，不静默补单位。
- B 实现产出乘数、Rasmussen 后向关联、中心性方向说明和二维分类；HEM 独立为一个有解析算例的任务。
- D/E 提供私人数据路径配置、数据 SHA 与方法快照、三份实际可跑教程，并对 metadata unknown 做适用性门控。
- C 与上述任务同时编写需求冲击的机制合同和零冲击解析测试，不等待所有 loader 或网络算法完成。
- 验收：真实数据仅本地验证；原始/聚合粒度和会计恒等式匹配；二维比较不直接合成无依据总分。
- 1302 节点中的零产出节点须显式保留/剔除记录并核验零行列，不能通过 nan_to_num 消失。

### 之后按研究需求滚动排序

| 小流程 | 能力增量 | 可并行工作 | 放行条件 |
| --- | --- | --- | --- |
| 需求冲击 | ShockScenario + Leontief demand model + SimulationResult | 冲击合同、解析对照、结果 schema | Δx=LΔy，零冲击零损失，解释是需求冲击而不是产能下降 |
| 关键性 | HEM、前/后向关联、网络节点比较 | IO 方法、结构方法、二维图表 | 归一化/方向明确；不把结构平均得分叫规模贡献 |
| 产能约束 | C0/C1 基准配给与产能模型 | 配给规则、极端测试、对比配置 | 产出不超过产能，投入可行、无冲击基准保持；明确稀缺投入规则 |
| 双韧性 | 功能与拓扑序列及损失面积 | 指标定义、曲线测试、结果导出 | 功能指标来自经济状态；拓扑指标来自图，保留时间单位和删失 |
| 历史 SIR 迁移 | 保留论文条件模拟支路 | 参数合同、基准对照、反例 | 修复边界缺陷；历史结果差异量化；不混称功能韧性 |
| 时间与稀疏化 | quantile/top-k/backbone、社区演化 | 过滤合同、社区方向、跨年口径 | 弱边、不可达与源表断点均报告；不从突变推断经济因果 |
| 恢复与替代 | 产能恢复、供应替代或重连的单一机制 | 策略对象、成本约束、恢复基准 | 真正恢复经济状态；重连有供应/容量/成本约束 |
| MRIO 扩展 | 地区×行业、国内/跨区分解和其他数据库 | 不同 adapters、共享测试 | region/country/sector 坐标与映射可追溯，禁止猜行业名 |
| 图学习 | 可选 PyG/GNN 与传统预测基线 | 数据划分、传统模型、图模型 | 不泄漏未来，时间外样本比较；attention 不当因果解释 |

V1.5 关键性比较不会被 GNN 或大规模级联挤掉；图学习只在有预测目标和有效样本时进入下一轮。

## 四类核心对象的合同

| 对象 | 本轮/当前状态 | 约定及扩展边界 |
| --- | --- | --- |
| IOSystem | 首轮实现 | Z 供给行/使用列，x，显式可选 y，唯一代码和 metadata；完整 A/L 不被网络阈值改动 |
| NetworkSystem | 首轮实现 | 过滤后矩阵、节点顺序、图、阈值/方向/距离/归一化；图与矩阵不一致时拒绝指标计算 |
| ShockScenario | 设计待迭代 02/后续实现 | target 必须能解析到稳定节点；区分 demand/capacity/edge，magnitude 定义不共用含糊单位 |
| SimulationResult | 设计待模型切片实现 | history 与时间单位、经济状态、拓扑序列、恢复/删失和方法 metadata；未计算字段不填伪造零 |

本轮不会为了“目录齐全”增加空的模拟器或承诺尚不存在的 simulate API。
未知插件/配置必须拒绝，不自动换成另一个模型。普通 IO 功能不能强制安装 Torch、Gensim 或 Node2vec。

## 科学边界与审查准则

- `A_ij=Z_ij/x_j` 是完整技术系数；`B_ij=Z_ij/x_i` 是分配系数。不能用同一名称混写。
- L 从完整 A 计算，先核验生产性条件；即使可逆也不代表满足 `rho(A)<1`。近临界条件数和残差诊断需单独完善。
- 图中的自环政策和最短路距离单独记录，不反向修改 IO 核算矩阵。
- 有向中心性记录入向/出向；对称化社区明确说明它丢失方向，而不是同一指标的无成本替换。
- `y_physical` 与含统计调整的 `y_accounting` 分开；投入侧进口不重复扣进输出侧 y。残差调整不伪装成实际增加值。
- 交易削弱、删除节点、降低产能、改变最终需求是不同实验。固定 x 增强交易不是投入产出再平衡，也不是投资预算。
- SIR 时间是模型时间；配置标定不是实测估计。恢复时间需同时报告风险峰值、范围和负担，删失不能记零。
- 结构指标、功能损失和因果政策效果分开命名。当前包输出结构测度/乘数，不输出综合韧性认定。

## 每次改动的监督与验收

一个任务经过 `Ready -> Implementing -> Verification -> Independent Review -> Local Ready -> Remote CI -> Merge`。
任一验证失败回到当前任务，不等整体项目结束再修。旧结果变化需要独立研究变更记录，不能无声更新 snapshot。

每个改动至少留下六条证据：

1. 问题及影响范围：是哪一个输入、定义或使用流程。
2. 前后差异：可复现负例/解析值/旧基准与新基准，而非“应该没问题”。
3. 方法说明：公式、方向、参数、单位和适用条件。
4. 执行证据：具体测试命令、环境、返回结果和失败限制。
5. 独立复审：非作者发现、修复和复验；AI 交叉复核不冒充维护者批准。
6. 放行决定：local ready、远程 CI 未运行、研究用途待授权等状态分开。

测试分为四层：Unit 检查公式和边界；Integration 检查完整小流程；Regression 保留稳定例子的数值；Scientific 检查守恒、方向、零冲击、可行约束和恢复极限。
首轮跨环境 CI 设置 Python 3.10/3.12，但在真正推送前不能声称 Linux 或第二个 Python 环境已跑通。

## GitHub 协作和公开门禁

- main 作为稳定入口；小 feature/work 分支完成一个问题，不要求再维护长期 develop。
- 用现有 Issue/PR 模板记录 task、method、data、bug、paper、documentation；每个 PR 尽量只含一个可独立审核的小切片。
- 组员权限、CODEOWNERS 与 main 保护必须由实际维护者确认；没有认证时不伪造远程 Issue、PR 或保护规则。
- 原始表、聚合 CSV、论文、私人路径、授权结果、凭据不进公开源码；所有权不明时按不可公开处理。
- 发布文件逐项核验 wheel/sdist 内容；通用递归打包不能用作公开发行。
- dev 版本先供组内试用；稳定发布才补 CITATION.cff 的确认作者/版本，DOI 仅在真正注册后填写。

## 成功标准

两个未参与核心编写的组员，能够按 README 在新环境完成样例，再用私有数据 adapter 重跑自己的单年分析；他们的差异来自配置，而不是各自复制修改核心。
正式里程碑还需三份可运行教程、四类测试、版本追溯、方法解释、关键性二维比较和至少一个经济机制明确的冲击流程。
这些标准须逐轮验证，首轮包安装成功不代表最终课题组平台已经建成。
