# 复杂网络计算路径审查与下一步方案

日期：2026-10-20。范围：当前网站的 `server/topology.py`、`src/topology-layout.js`、`src/topology.js`，及仓库 `src/ionet/core/io_system.py`、`src/ionet/network/build.py`。本次没有替换生产环境的网络方法。以下区分已核验事实与待实施方案。

## 结论

当前实现作为“有向加权投入产出结构浏览器”合理，并非已经完成的产业链韧性模型。优先改善展示骨架、参数敏感性和经济解释，不建议仅换成更复杂的布局或更炫的三维图。

## 已核验的正确做法

- 行供应、列使用，`A_ij = Z_ij / x_j`；全国行业和省际层级先汇总 Z 和 x，再计算 A，避免直接平均系数。
- 自环只从网络视图移除，不修改原始经济核算矩阵；零产出节点不随意删除，零产出与非零交易矛盾时拒绝构网。
- 全部阈值边用于度、强度、密度统计；Top-K 仅限制画面。邻居接口也查询全部阈值边，而非仅查询画面上的边。
- 多年共用节点坐标和强度尺度，避免逐年重新布局制造虚假的“位置演化”。
- 记录源文件 SHA-256、构网参数、内核及适配器指纹；价格、单位、行业代码和 2005–2007 年来源断点的限制没有被隐藏。
- 2026-10-20 运行 `scripts/test_topology.py`：8 项测试通过，含真实年度与 HTTP 接口。

## 实际数据诊断

用 `scripts/audit-topology.py` 只读运行本地 2023 年数据，A ≥ 0.005、展示上限 250。详细结果位于 `.artifacts/topology/method-audit-20261020.json`，附源哈希。下表“权重占比”是所展示 A 系数之和占阈值网络 A 系数之和，不是 GDP 或交易额覆盖率。

| 层级 | 节点数 | 阈值全网边数 | 展示边数 | 展示权重占比 | 全网有边但画面无边的节点 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全国行业 | 42 | 551 | 250 | 81.07% | 0 |
| 省际 | 31 | 511 | 250 | 79.17% | 0 |
| 省份 × 行业 | 1302 | 23746 | 250 | 11.81% | 953 |

1302 节点网络实际孤立节点为 23，不是画面上所有“没有连线”的点。全局 Top-K 对小网络尚可，对大网络会明显隐藏局部供应关系。

同一 2023 年全国行业网络，阈值从 0、0.001、0.005、0.01 到 0.02，边数分别为 1619、997、551、379、240。因此绝对阈值不是无关紧要的显示参数。不能将不同聚合层级下相同阈值当作同等过滤强度。

## 建议的计算分层

### 1. 经济矩阵层

保留含对角元的原始 Z、x、明确边界的最终需求 y。区分两种问题：

- 使用部门的投入依赖：`A_ij = Z_ij / x_j`。
- 供应部门的销售去向：`B_ij = Z_ij / x_i`。B 是销售分配系数，不应自动解释成可用于供给冲击因果识别的 Ghosh 模型。

金额网络 Z 用于规模，A/B 用于不同依赖视角；A 消除了共同货币单位缩放，但不自动消除相对价格变化。保持来源、价格口径和估算数据的不确定性提示。

### 2. 科研分析层

以全矩阵/明确阈值网络作为分析对象；保留当前强度指标，同时分开报告上游和下游，不把两者相加后的排行直接命名为“关键行业风险”。可逐步加入：

- 入/出强度、连通分量、上游集中度、供应多样性。
- 有向 PageRank 及反向 PageRank，但明确各自方向、阻尼系数、权重含义，不宣称它们天然优于经济损失排序。
- 多阈值敏感性：排名 Spearman 相关、Top-10 集合重合度、连通性、保留权重比例。
- 跨年排名与边权变化：固定节点身份和布局、展示变化值；价格与来源断点单独处理。

仓库 `structural_metrics` 使用 `distance = 1 / weight` 的最短路径效率。这是一个明确的结构代理假设，不等同于运输时间、生产替代成本或经济恢复速度。当前网站没有调用它来声称经济韧性。

### 3. 展示层

第一优先级：新增“局部重要边”视图，同时保留现在的 Top-K 对照。

1. 各节点分别提取最重要的入边与出边，取并集；再按剩余预算补充全局强边。
2. 显式报告节点连线覆盖率、展示边权占比、真实孤立节点数与仅因过滤而无可见边的节点数。
3. 不承诺任意低边数上限都能覆盖所有节点。预算不足时清楚说明覆盖损失，不能默默删除节点。
4. 节点点击后保留完整上/下游查询；默认按省份/行业组织，允许局部展开。
5. 增加 disparity filter 作为可选多尺度骨架，明确局部零模型、入/出方向、OR/AND 保边规则和 degree=1 边界。它优于全局阈值的场景需要数据对照，不是通用最优算法，也不等同于经济显著性。

当前 `sharedLayout` 对各年展示边取并集，固定 link distance/strength，以 d3-force 排布。这个布局能稳定比较年份，但节点接近不代表投入系数接近，也不代表地理距离。建议将布局移入 Web Worker、固定种子和布局版本，并允许“分组布局 / 骨架力导向 / 邻域视图”，而不是在主线程增加更多迭代。

### 4. 冲击与恢复层

需求冲击基线可用 `(I-A) Δx = Δy`，保留对角元；必须先校验核算边界、生产性及数值条件。它表示固定技术系数与可满足需求假设下的需求冲击，不是供给中断的通用模型。

供给中断与恢复应另设容量、关键投入、库存、替代、订单分配、恢复速度等状态。比较产出损失、累计损失、恢复时间，所有未校准参数标明情景假设。现有年度 IO 数据不能单独识别日度库存和恢复参数。不要将 SIR 感染率直接命名为真实停产概率。

## 工程实现路线（待实施，不是已经上线的功能）

```text
源文件及哈希
  -> 年度 Z/x 读取缓存（按数据版本失效）
  -> 层级聚合缓存（year, level）
  -> A/Z/B 及阈值分析结果（科学参数）
  -> CSR/CSC 邻接索引（稀疏后使用）
  -> 展示骨架（展示参数，与分析结果分离）
  -> Web Worker 布局缓存（节点集、骨架、种子、版本）
  -> 交互、完整邻居、年度比较与导出
```

当前 `neighbors()` 每次读取并聚合整年矩阵；仅变更 `max_edges` 也会产生新的完整构网缓存项。应优先拆分年度矩阵、分析参数和展示参数缓存，并设置字节级内存预算和相同请求合并。原始 Z 可能稠密，不能假定全部改 CSR 就一定更快。

若仅求少数冲击响应，不必显式构造整个 Leontief 逆矩阵；可复用分解并求解多右端项。例如以下是候选接口草图，未作为生产代码上线：

```python
# A 保留自投入；Y_shocks 每列是一个已定义的最终需求冲击。
# 上游先验证 rho(A) < 1、核算闭合、有限值与条件数。
from scipy.linalg import lu_factor, lu_solve
import numpy as np

M = np.eye(A.shape[0]) - A
factor = lu_factor(M)
delta_x = lu_solve(factor, Y_shocks)
relative_residual = np.linalg.norm(M @ delta_x - Y_shocks) / max(
    np.linalg.norm(Y_shocks), np.finfo(float).eps
)
```

这不是建议替换为稀疏近似的理由：生产分析是否保留完整矩阵、是否近似及误差容限须独立记录。求解残差小也不证明模型有经济因果有效性。

## 敏捷迭代与验收

1. 显示骨架与覆盖诊断：小网络保持回归一致，1302 节点验证隐去连线的比例；切换视图不得改变科学指标。
2. 阈值敏感性与方向化指标：小型手算网络、不同阈值、零产出、极端值、全网邻居对照；输出排名稳定性报告。
3. 缓存与 Worker：测试冷热请求、同年邻居反复访问、多年生成与取消；报告实测延迟和内存，不能只用理论复杂度宣称提速。
4. 需求冲击基线：手算 IO 表、核算闭合、谱半径与残差测试。
5. 动态供给恢复：校准资料、参数敏感性、零冲击不变性、产出上界、恢复与累计损失检查，然后再讨论政策解释。
